Architecture Technique Unifiée - RUP & CVNU

Le Smart Contract Unifié : rup.sol

Afin de garantir une sécurité maximale, de réduire les coûts de transaction (gaz) et d'assurer une parfaite cohérence avec le Projet de Loi Constitutionnelle, l'infrastructure s'articule désormais autour d'un contrat intelligent unique et centralisé : rup.sol.

Mise en conformité juridique : Ce contrat unifié transpose fidèlement les exigences du Code Général des Impôts (collecte TVA), du Code du Travail (paliers de valorisation) et du Code Monétaire et Financier (sécurisation des versements automatiques).

Structure Monolithique Sécurisée (rup.sol)

1. Trésorerie Collecte & Audit (TVA)
2. CVNU Évaluation & 11 Paliers
3. Distribution Paiements Sécurisés

1. Module de Trésorerie (La Collecte)

Code Général des Impôts (Art. 256)

Ce module gère la réception de la fraction de TVA allouée au financement du RUP.

  • Transparence Publique : Chaque versement de TVA déclenche l'événement PaymentReceived. L'incrémentation de la variable totalCollectedTVA permet un audit citoyen en temps réel.
  • Garantie de Solvabilité : La fonction _checkSolvency s'assure que le contrat dispose toujours des liquidités nécessaires avant d'autoriser la moindre transaction sortante.

2. Module CVNU (Le Moteur de Compétences)

Code du Travail (Art. L3222-1)

C'est ici qu'est évalué le Curriculum Vitae Numérique Universel du citoyen pour calculer le montant de son allocation.

  • Exigence de Certification : L'algorithme vérifie le statut isCertified. Seules les compétences officiellement validées génèrent du score.
  • Barème Discret (11 Paliers) : Conformément au projet de réforme, le calcul est échelonné. Le citoyen évolue du Palier 0 (socle minimal) au Palier 10 (plafond d'excellence).
  • Encadrement Financier : Le RUP est strictement borné. La fonction calculateRup garantit un revenu minimum de 700 € et un maximum infranchissable de 7500 €.

3. Module de Distribution (Le Paiement Sécurisé)

Code Monétaire & Financier / RGPD

Ce module assure le transfert des fonds vers le citoyen, en faisant le pont entre la blockchain et le monde réel.

  • Confidentialité (RIB Haché) : Le contrat ne stocke jamais de données bancaires en clair. Le RIB est remplacé par une empreinte cryptographique (bytes32 _ribHash), garantissant l'anonymat sur le registre public.
  • Prévention des doubles versements : Le système horodate chaque paiement. La variable PAYMENT_INTERVAL = 28 days bloque techniquement toute tentative de versement multiple au cours d'un même mois pour un même citoyen.
  • Sécurité Anti-Hack : Le paiement utilise la méthode recommandée call combinée au modificateur nonReentrant d'OpenZeppelin, immunisant les fonds publics contre les attaques de type réentrance.
  • Conversion Monétaire : Le contrat opère une conversion mathématique précise pour transformer la valeur fiduciaire du RUP (ex: 750) en unité transactionnelle blockchain (Wei).
